**این بخش چه کاری انجام می‌دهد؟**

Routing Safety تضمین می‌کند آدرس نامعتبر یا خطای سطح Route باعث صفحه سفید یا خروج کاربر از ساختار سامانه نشود. 404 داخل App Shell نمایش داده می‌شود و خطاهای Route با پیام کنترل‌شده مدیریت می‌شوند.

**امکانات و خروجی قابل استفاده**

**•** صفحه 404 استاندارد با بازگشت به داشبورد.

**•** Route Error Boundary برای خطاهای Render/Route.

**•** پیام‌های کنترل‌شده برای 403، 404 و 5xx در سطح Route.

**•** عدم نمایش Stack Trace و Exception داخلی به کاربر نهایی.

**نحوه استفاده**

**•** Route ناشناخته باید به NotFoundPage ختم شود.

**•** خطای سطح Route باید به RouteErrorPage برسد و کاربر گزینه تلاش مجدد یا بازگشت داشته باشد.

**•** خطاهای Feature-level همچنان می‌توانند با ErrorState داخل همان Page نمایش داده شوند.

**قواعد و نکات مهم**

**•** Route Error جایگزین مدیریت خطاهای API در Feature نیست؛ هر کدام مسئولیت جدا دارند.

**•** در Presentation مشتری، پیام‌ها باید کاربرپسند و بدون جزئیات فنی باشند.
