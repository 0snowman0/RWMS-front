**معماری ماژولار فرانت‌اند**

مرزبندی app / modules / shared و قرارداد توسعه Featureها

**این بخش چه کاری انجام می‌دهد؟**

معماری فرانت RWMS طوری تنظیم شده که با بزرگ شدن سامانه، Featureها از هم جدا بمانند و هر ماژول مالک Pageها، APIها، Hookها، Serviceها، Schemaها و Typeهای مربوط به دامنه خودش باشد. shared فقط برای قابلیت‌های واقعاً عمومی استفاده می‌شود.

**امکانات و خروجی قابل استفاده**

**•** تفکیک روشن بین تنظیمات سطح برنامه، ماژول‌های کسب‌وکار و اجزای عمومی.

**•** امکان توسعه مستقل Category، Item، Waybill، Request، Warehouse و ماژول‌های آینده.

**•** کاهش importهای متقاطع و وابستگی‌های تصادفی بین Featureها.

**•** Public API هر ماژول از طریق index.ts قابل کنترل است.

**•** ساختار آماده برای بزرگ شدن پروژه بدون تبدیل شدن به مجموعه‌ای از Pageهای حجیم.

**نمای سریع**

| **موضوع**    | **راهنمای کاربردی**                                 |
| ------------ | --------------------------------------------------- |
| **app**      | Router، Layout، Provider و Configuration سطح برنامه |
| **modules**  | Featureهای کسب‌وکار و صفحات دامنه‌ای                |
| **shared**   | UI، API Client، Utility، Hook و Type عمومی          |
| **index.ts** | مرز عمومی هر ماژول و محل Exportهای مورد نیاز بیرون  |

**نحوه استفاده**

**•** کدهای دامنه‌ای مثل ItemTable یا CategoryForm داخل همان ماژول قرار بگیرند، نه shared.

**•** Component عمومی مانند Button یا Dialog در shared/ui قرار می‌گیرد.

**•** Page وظیفه ترکیب اجزا و هماهنگی سطح Route را دارد و نباید تمام منطق Feature در آن نوشته شود.

**•** API فقط ارتباط HTTP را مدیریت می‌کند؛ منطق دامنه در Service/Hook مناسب قرار می‌گیرد.

**•** فولدر جدید فقط وقتی ساخته شود که واقعاً محتوا و مسئولیت مشخص دارد.

**قواعد و نکات مهم**

**•** shared نباید تبدیل به محل ریختن هر چیزی شود.

**•** وابستگی ماژول‌های Business به app باید حداقلی باشد.

**•** Featureها بهتر است از Public API یکدیگر استفاده کنند و به فایل‌های داخلی همدیگر وابسته نشوند.

**•** برای State سراسری فقط زمانی ابزار اضافه شود که نیاز واقعی Client State وجود داشته باشد.

**در ادامه پروژه**

**•** ماژول‌های فاز ۱ با همین قرارداد ساخته می‌شوند و ساختار داخلی هر Feature هنگام شروع آن Feature تکمیل خواهد شد.
