**این بخش چه کاری انجام می‌دهد؟**

این بخش سه وضعیت پرتکرار صفحات داده‌محور را استاندارد کرده است تا کاربر در کل سامانه پیام‌ها و ظاهر یکسانی ببیند و هر Feature حالت Loading یا Error مستقل نسازد.

**امکانات و خروجی قابل استفاده**

**•** LoadingState برای دریافت داده یا انتظار کوتاه.

**•** EmptyState برای نبود رکورد و امکان نمایش Action اختیاری.

**•** ErrorState برای خطاهای قابل نمایش به کاربر و Action مانند تلاش مجدد.

**•** ظاهر هماهنگ با Light/Dark و Design Tokenها.

**نحوه استفاده**

**•** در Queryهای صفحه به‌جای Spinnerهای پراکنده از LoadingState استفاده شود.

**•** EmptyState باید متن متناسب با Context داشته باشد؛ مثلاً «هنوز بارنامه‌ای ثبت نشده است».

**•** برای خطاهای فنی جزئیات داخلی یا Stack Trace به کاربر نشان داده نشود.

**•** در ErrorState در صورت امکان یک اقدام روشن مثل تلاش مجدد ارائه شود.

**قواعد و نکات مهم**

**•** پیام Empty با Error متفاوت است؛ نبود داده خطا محسوب نمی‌شود.

**•** Loading طولانی بهتر است با متن Contextual همراه شود.

**•** جزئیات فنی خطا باید در Logging/Monitoring ثبت شوند، نه در رابط کاربر.
