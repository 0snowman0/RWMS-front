**TanStack Query Foundation**

مدیریت Server State، Cache، Retry و Mutation در کل پروژه

**این بخش چه کاری انجام می‌دهد؟**

TanStack Query مسئول داده‌ای است که منبع اصلی آن Backend است. این لایه Cache، Freshness، Refetch و Mutation را استاندارد می‌کند تا هر Feature مدیریت Loading/Cache و Retry را از صفر پیاده‌سازی نکند.

**امکانات و خروجی قابل استفاده**

**•** QueryClient مرکزی و Provider سراسری.

**•** Stale Time پیش‌فرض ۳۰ ثانیه و نگهداری داده غیرفعال تا ۱۰ دقیقه.

**•** عدم Refetch ناگهانی صرفاً با تغییر Tab مرورگر.

**•** Refetch پس از بازگشت اتصال شبکه.

**•** Retry محدود برای Network/408/5xx و عدم Retry برای 401/403/422.

**•** Mutationها به‌صورت پیش‌فرض Retry نمی‌شوند.

**نحوه استفاده**

**•** خواندن داده Backend با useQuery و عملیات تغییر با useMutation انجام شود.

**•** پس از Mutation موفق، Queryهای مرتبط invalidate یا update شوند.

**•** Query Key هر Feature باید ساختار مشخص و قابل پیش‌بینی داشته باشد.

**•** برای صفحه‌های خاص می‌توان staleTime را Override کرد؛ Default سراسری فقط نقطه شروع است.

**قواعد و نکات مهم**

**•** Client State محلی با Server State اشتباه نشود؛ TanStack Query جای useState یا Form State نیست.

**•** POST/PUT/PATCH/DELETE به‌صورت عمومی Auto-Retry نمی‌شوند تا ثبت تکراری ایجاد نشود.

**•** 401 باید توسط API/Auth Flow مدیریت شود، نه Retry خودکار Query.

**در ادامه پروژه**

**•** هر ماژول Feature Hookهای Query و Mutation خودش را نزدیک همان ماژول نگه می‌دارد.
